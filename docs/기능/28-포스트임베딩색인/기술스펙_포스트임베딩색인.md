# 기술스펙_포스트임베딩색인

- 기능요청: [B0](https://github.com/MEV-SW/mint-server/issues/28) / 인터페이스 정의: [API스펙_포스트임베딩색인](API스펙_포스트임베딩색인.md)
- 작성: 채윤성 / 승인: 리뷰 없음(§3 — 단독 리포, 승인 상대 없음)

## 변경 범위

- `app/core/config.py`: `bedrock_embedding_model`(기본 `cohere.embed-multilingual-v3`), `bedrock_embedding_region`(기본 `us-east-1`), `bedrock_embedding_dims`(기본 `1024`) 추가. 기존 `bedrock_image_region` 패턴과 동일하게 모델별 리전 분리.
- `app/services/embedding_client.py` 신설: `embed_text(text, *, input_type="search_document") -> list[float] | None` — [`create_bedrock_runtime_client`](https://github.com/MEV-SW/mint-server/blob/main/app/services/bedrock_runtime.py)로 Cohere 임베딩 호출. 빈 텍스트는 호출 없이 `None`. 실패(자격증명·쿼터·네트워크)는 삼키지 않고 그대로 raise — 호출부가 기존 아웃박스 재시도에 태울 수 있게. `post_embedding_text(title, summary)` — `title + "\n" + summary`, 요약 없으면 제목만.
- `app/search/index_mapping.py`: `_text_properties`에 `embedding`(dense_vector, dims=`settings.bedrock_embedding_dims`, cosine) 추가.
- `app/search/post_content.py`: `_build_index_document`가 `embed_text(post_embedding_text(post.title, content.summary))`를 `"embedding"` 필드로 포함. `save_post_content`에서 문서 빌드(`_build_index_document` 호출)를 기존 `try` 블록 **안으로** 옮겨서 — 임베딩 실패가 `client.index()` 실패와 동일하게 처리되어(`except Exception`) 아웃박스에 재큐잉되게 한다(이전엔 문서 빌드가 `try` 밖에 있어 실패 시 그대로 예외가 터졌음).
- `scripts/backfill_post_embeddings.py` 신설: 최근 N일 posts를 `sync_post_metadata`로 재색인.
- DB: 변경 없음(임베딩은 PG가 아니라 ES에만 저장).

## DB 스키마 변경분

없음. ES 인덱스 매핑에 `embedding` 필드 추가(위 API스펙의 "Elasticsearch 매핑 변경" 참고 — 기존 인덱스는 자동 반영 안 됨).

## 핵심 흐름 (시퀀스 1-2개)

API스펙의 "임베딩 파이프라인 계약" 절 참고 — 정상 경로·실패 경로 시퀀스가 이미 거기 있고 여기서 반복하지 않는다.

## 외부 의존성

- Amazon Bedrock (`cohere.embed-multilingual-v3`, `us-east-1`). `boto3` 이미 의존성에 있음(다른 Bedrock 기능이 사용 중).
- Elasticsearch — 기존 `search_uses_elasticsearch`가 꺼져 있으면(`SEARCH_BACKEND=postgres`, 기본값) 이 카드의 코드 경로 자체가 실행되지 않는다(`save_post_content`가 그 시점에 조기 반환).

## 검증

로컬에 Bedrock·ES 자격증명이 없어 실제 네트워크 호출은 못 붙여봤다. 대신:
- `build_posts_index_body()`가 `dims=1024` dense_vector를 포함하는지 직접 호출로 확인.
- `embed_text()`를 Bedrock 클라이언트 모킹(`invoke_model` 응답 고정)으로 호출 — 정상 반환값, 빈 텍스트 단락(호출 안 함) 확인.
- `save_post_content()`를 ES 클라이언트 모킹 + `embed_text` 모킹(성공/실패 둘 다)으로 호출 — 실패 시 `SearchIndexQueue`에 정확히 1건 큐잉되고 `client.index()`가 호출되지 않음, 성공 시 색인 문서에 `embedding` 필드가 포함됨을 확인.
- 실제 Bedrock/ES 붙는 통합 확인은 스테이징에서 `ELASTICSEARCH_URL`·`BEDROCK_API_KEY` 설정 후 `backfill_post_embeddings.py --days 1`로 해야 한다(후속 배포 체크리스트 항목).

## flag

없음 — 기존 `SEARCH_BACKEND=elasticsearch|dual`가 이미 이 파이프라인 전체의 게이트다. 별도 flag를 추가하면 두 스위치가 서로 다른 걸 막아 혼란만 커진다.
